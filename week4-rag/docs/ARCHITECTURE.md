# RAG 文档问答 · 一页架构说明

> 2026-11-18 ｜ 第 4 周交付物 ｜ 语料：示例团队手册（7 节）｜ 模型：智谱 `glm-4-flash` + `embedding-3`
> 代码：`week4-rag/rag.py`（零框架版，逐行可读）、`week4-rag/langchain_demo.py`（LangChain 版）

## 链路：一次提问发生了什么

```
[离线 · 只做一次]  team-handbook.md
                    → 按 ## 分节 → 切块(220 字 / 重叠 40) → embedding-3(256 维)
                    → 向量归一化 → data/index.json

[在线 · 每次提问]  问题 → embedding-3 → 与全部片段算余弦相似度
                    → 过阈值 0.55 取 top-3 → 片段+标题拼进 user 消息
                    → glm-4-flash(temperature 0.2) → 答案 + 【来源】
                    ↘ 无片段过阈值 → 直接返回「资料里没有提到」，不调用模型
```

## 六个环节的选择与依据

| # | 环节 | 选型 | 为什么 / 实测 |
|---|---|---|---|
| 1 | 数据源与切分 | Markdown 二级标题分节，节内 220 字滑窗、重叠 40 字 | 标题天然就是答案出处；重叠避免一句话被切断后语义丢失。当前 7 节 → 7 个片段 |
| 2 | Embedding 与存储 | `embedding-3`，256 维；归一化后存 `data/index.json` | 智谱 `/v4/embeddings` 单次最多 64 条；预归一化后一次点积就是余弦。索引落盘，避免每问一次就为整份文档重复付费 |
| 3 | 检索参数 | 余弦相似度，`top_k=3`，`min_score=0.55` | 阈值不是拍脑袋：`verify.py` 实测资料内最低 **0.634**、资料外最高 **0.489**，取中间留余量。用 numpy 线性扫描，7 块规模够用 |
| 4 | Prompt 模板 | system 写死四条规则；user = `【资料】命中片段【问题】` | 片段连同小节标题一起进上下文，模型才标得出处；明确禁止使用资料外知识 |
| 5 | 模型与温度 | `glm-4-flash`，`temperature=0.2` | 文档问答要可复现，低温减少自由发挥。实测单次问答 **292 输入 / 24 输出 token** |
| 6 | 兜底与验收 | 无命中直接返回固定话术；`verify.py` 5 例 | 机制上保证"资料外不硬编"：不调用模型就没机会编。实测 **5/5 通过**，3 个资料内问题答案带正确来源，2 个资料外问题明确说没有 |

## 为什么提供两个版本

`rag.py` 只用 `requests` + `numpy`，把切分、向量化、检索、拼装全摊开，用来讲清 RAG 到底做了什么；
`langchain_demo.py` 用 `RecursiveCharacterTextSplitter`、`Embeddings` 抽象类和 `ChatOpenAI` 接管同样三步，
对齐任务卡要求的框架。两版检索都手写 numpy 余弦，是为了让 top-k 与阈值的作用看得见。

## 成本、限制与下一步

- **成本**：建索引 7 个片段约 1 次 embedding 调用；每次提问 1 次 embedding + 1 次 chat。索引缓存是这里最有效的省钱手段。
- **限制**：① 语料是编的示例文档，等真实团队文档替换；② 阈值 0.55 与这份语料绑定，换文档必须重标定；③ 无重排、无多轮对话、无权限控制；④ 内存线性扫描，上万片段就不适用。
- **上生产要改**：换 Chroma / FAISS / pgvector 做索引；加召回后重排；建 20 条测试问题记录召回率与准确率；把来源做成可点击引用；按人过滤可见文档。
- **验收口径**：能引用原文、能对资料外的问题说"不知道"（对应学习计划阶段 4 的验收标准）。这两条已由 `verify.py` 固化成可重复执行的检查。
