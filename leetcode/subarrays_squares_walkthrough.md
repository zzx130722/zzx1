## 一、先把题目翻译成人话

题目要的是：**把数组里所有连续片段都看一遍，每个片段数一数有几个不同的数，平方，全加起来。**

"子数组"就是**连续的一段**，不能跳着取。长度为 n 的数组，子数组一共 `n(n+1)/2` 个
（起点有 n 种，终点至少和起点相同）。

用示例 1 `nums = [1,2,1]` 走一遍，一共 6 个：

| 子数组 | 里面有哪些不同的数 | 不同计数 | 平方 |
|---|---|---|---|
| `[1]` | {1} | 1 | 1 |
| `[2]` | {2} | 1 | 1 |
| `[1]` | {1} | 1 | 1 |
| `[1,2]` | {1,2} | 2 | 4 |
| `[2,1]` | {2,1} | 2 | 4 |
| `[1,2,1]` | {1,2} | 2 | 4 |

合计 1+1+1+4+4+4 = **15**。注意最后一行：`1` 出现了两次，但**只算一个**。

> **平方在这里的作用**：它不是装饰。`1,1,1,2,2,2` 的和是 9，平方和是 15。
> 平方让"不同计数大的子数组"权重更高，也让增量维护必须同时盯住
> **ΣA[l]** 和 **ΣA[l]²** 两个量（下面会看到为什么）。

## 二、为什么"一个个数"会超时

最直观的写法：枚举起点 `i`，向右扩展 `j`，用集合维护不同值。

```python
for i in range(n):
    seen = set()
    for j in range(i, n):
        seen.add(nums[j])
        ans += len(seen) ** 2
```

这是 O(n²)：n = 100 时约 5000 次操作，轻松；n = 10⁵ 时约 50 亿次，
**本机实测约 166 秒** —— 而判题机只给几秒。所以困难版必须换思路。

## 三、关键一步：换个方向看「子数组」

上面是"按起点分组"。改成**按右端点分组**：

> 求出：**所有以 0 结尾的子数组**的答案 + **所有以 1 结尾的** + …… + **所有以 n-1 结尾的**。

这样分有什么好处？因为**右端点每往右挪一格，所有"以该点为终点"的子数组都同时被影响** ——
这正是"批量更新"的信号，而批量更新正是数据结构最擅长的事。

定义 `A[l]` = **子数组 `nums[l..r]` 的不同计数**（固定当前右端点 `r`，`l` 从 0 到 r）。

那么：

> **「以 r 结尾的所有子数组的答案」= `A[0]² + A[1]² + ... + A[r]²`**

先看 `r = 0`（只有 `[1]`）时：`A = [1, 0, 0]`，平方和 1 ✓
再看 `r = 1`（`nums[0..1] = [1,2]`）：`A = [2, 1, 0]`，平方和 4+1 = 5 ✓
（对应子数组 `[1,2]`→2、`[2]`→1）
最后 `r = 2`（`nums = [1,2,1]`）：`A = [2, 2, 1]`，平方和 4+4+1 = 9 ✓
（对应 `[1,2,1]`→2、`[2,1]`→2、`[1]`→1）

**1 + 5 + 9 = 15**，正好是答案。方向对了。

## 四、r 每往右挪一格，A 怎么变？

这是全题最核心的一句话。设新元素是 `v = nums[r]`，`v` **上一次出现的下标是 `p`**
（第一次出现记作 `p = -1`）：

| `l` 的范围 | 子数组 `nums[l..r]` 里 `v` 的角色 | `A[l]` 怎么变 |
|---|---|---|
| `p+1 ≤ l ≤ r` | `v` 在 `nums[l..r-1]` 里**没出现过** → 是新面孔 | **+1** |
| `0 ≤ l ≤ p` | `v` 在 `nums[l..r-1]` 里**已经出现过** | **不变** |

**为什么分界线是 `p`？** 因为 `l ≤ p` 时子数组已经把上一个 `v`（下标 p）包进来了，
新的 `v` 只是重复；`l > p` 时上一个 `v` 被排除在外，新来的 `v` 就是第一个。

用 `nums = [1,2,1]` 走第三步（`r = 2`，`v = 1`，`p = 0`）验证：

- `l = 0`：`[1,2,1]`，`1` 早在下标 0 出现过 → 不变，还是 2 ✓
- `l = 1`：`[2,1]`，之前是 `[2]` 只有 1 种，现在 `1` 进来了 → 2 ✓（1+1）
- `l = 2`：`[1]`，从空变成 1 种 → +1 ✓

对上了。

**所以每挪一格，只需要做一个操作：把 `A[p+1 .. r]` 这一段整体加 1。**

## 五、平方和怎么"增量"维护？

问题来了：我们不是要 `ΣA[l]`（一次求和就够了），要的是 **`ΣA[l]²`（平方和）**。
给一段区间每个数都加 1，平方和会怎么变？

单个数看：`(x+1)² - x² = 2x + 1`。
所以**整段 [p+1, r] 加 1 之后，平方和总共增加**：

```
Σ(2·A[l] + 1)  =  2 · ΣA[l]  +  区间长度
```

也就是说，**只要知道这一段当前的和（`ΣA[l]`），就能直接算出平方和的新值**，
不用去碰每一个 `A[l]`。

于是我们只要维护一个数组 `A`，支持两件事：

1. **区间加**：`A[p+1..r]` 全部 +1
2. **区间求和**：`A[p+1..r]` 加起来是多少

这两个操作的组合，是**树状数组（Fenwick）** 的经典用法。

## 六、两个树状数组怎么做到"区间加 + 区间求和"

先记住一个式子。设 `D` 是 `A` 的**差分数组**（`D[i] = A[i] - A[i-1]`），那么：

- **区间加** `A[l..r] += v` ⟺ 差分上只改两个点：`D[l] += v`、`D[r+1] -= v`
- **前缀和**：`A[0] + ... + A[x] = (x+1)·ΣD[0..x] - Σ(j·D[j])`（j 从 0 到 x）

第二个式子不难推：`A[i]` 是 `D` 的前缀和，把 `Σ_{i≤x} Σ_{j≤i} D[j]` 交换求和顺序，
`D[j]` 就被累加了 `(x-j+1)` 次，拆开就是 `(x+1)·ΣD[j] - Σ j·D[j]`。

所以只需要**两个树状数组**：

- `d1` 存差分 `D` → 用来算 `ΣD[0..x]`
- `d2` 存 `j·D[j]` → 用来算 `Σj·D[j]`

代码里把它们写在同一个 `while` 循环里，省一半循环次数：

```python
def range_add(l, r, v):
    i = l + 1
    while i < size:
        d1[i] += v
        d2[i] += v * l
        i += i & -i
    i = r + 2
    while i < size:
        d1[i] -= v
        d2[i] -= v * (r + 1)
        i += i & -i

def prefix_A(x):                 # A[0] + ... + A[x]
    i = x + 1
    s1 = 0
    s2 = 0
    while i > 0:
        s1 += d1[i]
        s2 += d2[i]
        i -= i & -i
    return (x + 1) * s1 - s2
```

> `i & -i` 是"取最低位的 1"，树状数组靠它上下跳；`size = n + 2` 是因为内部下标整体右移一位，
> 而差分要处理 `D[r+1]`（`r+1` 最大等于 `n`），所以要多留两格。

## 七、主循环，一行一行看

```python
last = {}
ans = 0        # 最终答案（已取模）
total_sq = 0   # 当前状态下的 ΣA[l]²，也就是「以 r 结尾的答案」

for r, v in enumerate(nums):
    p = last.get(v, -1)                     # v 上一次出现的下标，没有则 -1

    span_sum = prefix_A(r) - prefix_A(p)    # Σ A[p+1..r]
    total_sq = (total_sq + 2 * span_sum + (r - p)) % MOD
    ans = (ans + total_sq) % MOD

    range_add(p + 1, r, 1)                  # 这两段 A[l] 各 +1
    last[v] = r                             # 记住 v 的新位置，供下次用
```

- `p = last.get(v, -1)`：查 `v` 上次在哪。**第一次出现时 `p = -1`**，
  这样 `p+1 = 0`，区间正好是 `[0, r]` —— 整段都是新面孔，逻辑统一，不用特判。
- `2 * span_sum + (r - p)`：就是第五节的 `2·ΣA[l] + 区间长度`，区间长度 = `r - (p+1) + 1 = r - p`。
- **先算 `total_sq` 再 `range_add`**：因为增量的公式用的是**加之前**的 `A`。顺序反了会算多。
- 每一步的 `total_sq` 都是"以 r 结尾的所有子数组"的答案，所以每步都累加到 `ans` 里。
- 每步都 `% MOD`：真值能到几万亿，**必须边走边取模**（实测 n=3000 时真值已是 6,759,003,750,500）。

## 八、取模不是可选项

两个版本的区别就在这：

| | 2913（简单版） | 2916（困难版） |
|---|---|---|
| 数据范围 | `n ≤ 100` | `n ≤ 10⁵` |
| 是否取模 | 不用（答案很小） | **必须**对 `10⁹+7` 取模 |
| 合格复杂度 | O(n²) 就行 | 必须 O(n log n) |

**拿简单版的暴力代码去交困难版，结果是超时（TLE）不是答案错** —— 因为算出来的数本身是对的。
反过来，**困难版的代码交简单版是完全没问题的**（`% MOD` 在小数据下不改变结果），
所以如果你不确定自己在做哪一道，交困难版那份最保险。

## 十、三个容易踩的坑

1. **`p` 的初值**。用 `p = -1`（而不是 0 或 `None`）能让"第一次出现"走同一条逻辑，
   省掉一个 `if`。写 0 的话 `l = 0` 这一段会被错误地当成"已经出现过"。
2. **先算增量、后更新数组**。顺序反过来，`span_sum` 拿到的就是更新后的和，`total_sq` 会偏大
   （实测 `[1,2,1]` 会算出 33 而不是 15）。
3. **`last` 要更新**。忘了写 `last[v] = r`，下一次遇到同一个 `v` 时 `p` 还是老的，
   每个重复值都会被当成新面孔。实测 `[1,2,1]` 会算出 20 而不是 15。
   ⚠️ **注意这个 bug 在"全不重复的数组"上完全看不出来**（那时 `p` 本来就一直是 -1），
   所以必须专门拿含重复值的用例测。

---

**一句话总结**：把"所有子数组"按右端点分组，每挪一格就把一段 `A` 整体加 1；
平方和的增量 = `2·区间和 + 区间长度`，所以只要一个支持"区间加 + 区间求和"的树状数组就能维护。
