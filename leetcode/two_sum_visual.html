两数之和 · 图解版

LeetCode 1. Two Sum　难度：简单　—— 点着按钮，看算法一轮一轮怎么走

先弄清题目在说什么

数组就是「一排格子」，下标就是「格子的编号」，Python 里从 0 开始数。

target = 9，也就是要在一排格子里挑两个，让里面的数加起来等于 9，然后报出这两格的编号。

答案：[0, 1]，因为 nums[0] + nums[1] = 2 + 7 = 9。

题目还有两条限制：一是「每种输入只会对应一个答案」（不用考虑找不到或多组答案）； 二是「不能使用两次相同的元素」—— 不能拿同一个格子用两遍。第二条后面会成为一个大坑。

1方法一：所有配对都试一遍

最直白的做法。这里故意换一个 target = 26，好让你看清循环是怎么一步步走完的。

第一个数 i 第二个数 j 命中
0 / 6 次尝试
点「试下一对」开始。
for i in range(len(nums)):
    for j in range(i + 1, len(nums)):      # 关键：从 i+1 开始
        if nums[i] + nums[j] == target:
            return [i, j]

为什么 j 要从 i+1 开始？两个原因：① 从 0 开始会出现 i==j，拿同一个格子自己配自己； ② 从 i+1 开始还能避免重复，因为 (0,1) 和 (1,0) 是同一对。

2方法二：边登记边查找（LeetCode 正解）

换一个思路 —— 不问「谁跟我配对」，而问「我还差谁」。差的那个人就是 target − 当前数。

正在看的数 命中
登记本（数字 → 它在几号格子）：（空）
第 0 / 3 轮
点「下一轮」开始。注意观察登记本是怎么一点点变多的。
seen = {}
for i, n in enumerate(nums):
    need = target - n
    if need in seen:            # 先查
        return [seen[need], i]
    seen[n] = i                 # 再存
return []

这就是 O(n)：每个格子只看一次，字典的查找和插入几乎不花时间。 对比方法一「每个格子都要回头问一遍前面的格子」，差别就在这里。

3最容易写错的地方：先查还是先存

用最刁钻的用例来验：nums = [3, 3]，target = 6。两个格子的数一样，但它们是两个不同的格子。

登记本：（空）
第 0 轮
选一种写法，然后点「下一轮」。

先查再存 —— 正确

查的是「我之前有没有见过你」。刚登记的自己属于「现在」，不算「之前」。

第 1 轮：查 3 → 空 → 登记。
第 2 轮：查 3 → 有 → 返回 [0, 1]

先存再查 —— 踩坑

一登记就立刻查到刚写进去的自己，等于让同一个格子和自己配对。

第 1 轮：登记 → 查 3 → 命中自己 → 返回 [0, 0]

seen[n] = i                 # 错：登记在前
if need in seen: ...
# nums=[3,3] → 返回 [0,0]，同一个格子用了两遍

示例 3 存在的意义，就是专门用来抓这个错误的。这也是为什么做题时要拿边界用例自测 —— 普通用例（比如 [2,7,11,15]）两个写法都能过，只有 [3,3] 能把错误暴露出来。

两种方法放一起比

看懂要多久快慢一点（要先理解字典）
时间复杂度O(n²)O(n)
空间复杂度O(1)O(n)（多存一个字典）
n = 100,000 实测约 238 秒（超时）0.019 秒
LeetCode 能过吗数据量大时超时能过

O(n²) 和 O(n) 差多少？格子数翻倍时，O(n²) 的耗时变成 4 倍，O(n) 只翻一倍。 数据量一大，差距是成倍拉开的，不是「快一点点」。

这叫做「用空间换时间」：多花一点内存（存了这个字典），换来快到飞起的查找。 这是算法里最常见的取舍之一。

该用哪个？学法建议

  • 提交到 LeetCode / 面试 → 用方法二。方法一会超时，而且面试官想看的正是「你会不会想到用哈希表」。
  • 只是理解题目 → 先用方法一，它不需要任何额外知识就能看懂。

推荐的学法：先自己写出方法一，再问自己「怎么才能不重复地问前面那些数」—— 顺着这个问题，你自然会想到方法二。这个「从笨办法走到聪明办法」的过程， 比直接背下方法二有价值得多。

三个新手最容易踩的坑

if nums[i] + nums[j] = target:          # 坑 1：等号写成一个，语法直接报错
if nums[i] + nums[j] == target:         # 对：比较要用两个等号
for j in range(len(nums)):              # 坑 2：内层从 0 开始，会拿自己配自己
for j in range(i + 1, len(nums)):       # 对：只跟后面的配对
seen[n] = i                             # 坑 3：先登记再查（见上面第 3 节）
if need in seen: ...                    # 对：先查，再登记

一个等号 = 是「赋值」，把右边存进左边；两个等号 == 是「比较」， 问左右相等吗，结果是 True 或 False。新手最常在这里栽。
