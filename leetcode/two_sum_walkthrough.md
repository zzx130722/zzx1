## 第 0 步：先把题目翻译成人话

> 给定一个整数数组 nums 和一个整数目标值 target，请你在该数组中找出和为目标值 target 的那两个整数，并返回它们的数组下标。

先把三个词的意思弄清楚：

**数组**就是**一排格子**，每个格子里装一个数。比如 `nums = [2, 7, 11, 15]`：

```
格子：    [0]   [1]   [2]   [3]
内容：     2     7     11    15
```

**下标**就是格子的**编号**，Python 里从 **0** 开始数（不是从 1）。

**`nums[i]`** 的意思是"第 i 号格子里装的那个数"。`nums[0]` 是 2，`nums[1]` 是 7。

所以题目的要求翻译过来就是：

> 在这排格子里挑出**两个格子**，让里面的数加起来正好等于 target，
> 然后告诉我这两个格子的**编号**。

题目还给了两条限制：

- **每种输入只会对应一个答案** —— 不用考虑"找不到"或者"有好几组答案"的情况，找到一组就能返回
- **不能使用两次相同的元素** —— 不能拿同一个格子用两遍（比如 `nums[0] + nums[0]`）

返回的编号**按什么顺序都行**，`[0,1]` 和 `[1,0]` 都算对。

## 方法一：两层循环（最直白的做法）

### 思路：把所有可能的两两组合都试一遍

一共 4 个格子，那就问：

- 0号和1号加起来对吗？
- 0号和2号呢？0号和3号呢？
- 1号和2号呢？1号和3号呢？
- 2号和3号呢？

全试一遍，总有一组是对的。

### 代码

```python
def two_sum(nums, target):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return [i, j]
    return []
```

### 逐行拆解

**第 1 行：`def two_sum(nums, target):`**

定义一个函数。`def` 是 "define"（定义）的缩写。
括号里的 `nums` 和 `target` 是**参数**——也就是别人调用这个函数时需要递给它两样东西：
装着数字的数组，和目标值。

末尾的冒号 `:` 表示"下面缩进的几行，都是这个函数的内容"。

**第 2 行：`for i in range(len(nums)):`**

`len(nums)` 是数组的长度，也就是格子个数（这里是 4）。
`range(4)` 会生成 `0, 1, 2, 3` 这四个数。

所以这一行的意思是：**让 `i` 依次等于 0、1、2、3**，每取一个值就执行一遍下面的内容。
`i` 代表**第一个数的格子编号**。

**第 3 行：`for j in range(i + 1, len(nums)):`**

这行嵌在上一行里面，叫**嵌套循环**。它会在 `i` 每取一个值时，完整地跑一遍。

`range(i + 1, 4)` 表示"从 `i+1` 开始，一直到 3"。
比如 `i` 是 0 时，`j` 就依次等于 1、2、3。

**为什么 `j` 要从 `i + 1` 开始？** 这是个关键问题，有两个原因：

1. 如果 `j` 从 0 开始，那 `i = 0, j = 0` 时就会拿 `nums[0]` 和它自己相加——
   同一个格子用了两遍，违反题目"不能使用两次相同的元素"这条限制。
2. 从 `i+1` 开始还能避免重复：`(0,1)` 和 `(1,0)` 是同一对，试一次就够了。

`j` 代表**第二个数的格子编号**。

**第 4 行：`if nums[i] + nums[j] == target:`**

把两个格子里的数加起来，看看是不是等于目标值。

注意这里用的是**两个等号** `==`。Python 里：

- 一个等号 `=` 是"赋值"，意思是"把右边的东西存进左边的变量"
- 两个等号 `==` 是"比较"，意思是"左边和右边相等吗"，结果是 `True` 或 `False`

新手最常犯的错就是这里写成了一个等号。

**第 5 行：`return [i, j]`**

一旦找到，立刻返回这两个编号。方括号 `[]` 表示这是一个**列表**（一串有顺序的东西）。

`return` 还有个副作用：**函数会立刻结束**。所以找到之后，后面的组合就不会再试了，省时间。

**第 6 行：`return []`**

这行写在两层循环**外面**（注意它的缩进和 `for` 一样，不是嵌在里面的）。
意思是：循环全部跑完还没返回，说明真的没找到，那就返回一个空列表。

> 严格说题目保证了"一定有答案"，所以这行**永远执行不到**。
> 但写上它是个好习惯——万一输入不符合假设，函数也不会返回一个莫名其妙的东西（`None`）让后面报错。

### 拿示例 1 走一遍

```
输入：nums = [2, 7, 11, 15], target = 9
```

| i | j | nums[i] | nums[j] | 相加 | 等于 9 吗 |
|---|---|---|---|---|---|
| 0 | 1 | 2 | 7 | **9** | ✅ 命中 |

第一组就命中了，返回 `[0, 1]`。

### 拿示例 3 走一遍（这个更值得看）

```
输入：nums = [3, 3], target = 6
```

| i | j | nums[i] | nums[j] | 相加 | 等于 6 吗 |
|---|---|---|---|---|---|
| 0 | 1 | 3 | 3 | **6** | ✅ 返回 [0, 1] |

两个格子里装的数一样（都是 3），但它们是**两个不同的格子**（编号 0 和 1），
所以可以一起用。这里返回 `[0, 1]` 是对的。

**但如果 `j` 从 0 开始写呢？**

| i | j | nums[i] | nums[j] | 相加 | 结果 |
|---|---|---|---|---|---|
| 0 | 0 | 3 | 3 | 6 | ❌ 返回 [0, 0] —— 同一个格子用了两遍！ |

**这就是为什么必须写 `range(i + 1, ...)`。** 示例 3 存在的意义，就是专门用来抓这个错误的。

### 这个解法的问题

数组有 4 个格子时，大约比较了 6 次，很快。但数字多了呢？

| 格子数 n | 大约比较次数 n²/2 | 实测感受 |
|---|---|---|
| 10 | 45 | 瞬间 |
| 3,000 | 450 万 | **0.21 秒**（实测） |
| 100,000 | 50 亿 | 外推约 **238 秒**，也就是快 4 分钟 —— LeetCode 直接判超时 |

> 上面那行 0.21 秒是这台机器上真跑出来的（`n=3000`）。
> 按 O(n²) 的规律放大到 10 万，就是 0.21 × (100000/3000)² ≈ 238 秒。

原因很清楚：**每遇到一个新数，我们都在重新问一遍"前面所有数"**。
问过的信息没有被记住，全白问了。

## 方法二：字典（又快又短，这是 LeetCode 的正解）

### 先理解"字典"是什么

Python 的字典（`dict`）就像一本**真的字典**：

- 你用"字"去查，立刻翻到它对应的"解释"
- 你**不需要**从第一页翻到最后一页去找

用代码写出来是这样：

```python
seen = {}          # 建一个空字典
seen[7] = 0        # 记录：数字 7 出现在 0 号格子
seen[3] = 5        # 记录：数字 3 出现在 5 号格子

print(seen)        # {7: 0, 3: 5}
print(seen[7])     # 0   —— 一句话就查到了
print(7 in seen)   # True —— 7 在不在字典里？
```

关键优势是：**不管字典里存了 3 条还是 300 万条记录，查一次的速度几乎一样快**。
（专业说法是这个操作的复杂度是 O(1)，下面会再解释。）

### 思路转换：从"到处问"变成"先记下来，再回头查"

方法一的瓶颈是：对每个数，都要去问前面所有数。

**换个角度想：**

假设我手上有数字 `n`，目标是 `target`。
我真正在找的那个"另一半"是谁？**就是 `target - n`。**

比如 `target = 9`，当前数字是 `2`，那我要找的就是 `9 - 2 = 7`。
只要 7 之前出现过，答案就到手了。

所以我们一边走，一边把走过的数字**登记**到一个字典里。
每到一个新格子，先算一下"我需要谁"，然后去字典里查一下——它在不在？

### 代码

```python
def two_sum(nums, target):
    seen = {}
    for i, n in enumerate(nums):
        need = target - n
        if need in seen:
            return [seen[need], i]
        seen[n] = i
    return []
```

还是 6 行，但快得多。

### 逐行拆解

**第 1 行：`def two_sum(nums, target):`**

和方法一完全一样。

**第 2 行：`seen = {}`**

建一个空字典，变量名叫 `seen`（"见过的"）。
它要扮演的角色是**登记本**：记下"这个数字，我在几号格子见过它"。

`{}` 是一对**空的**花括号，表示字典里现在什么都没有。

**第 3 行：`for i, n in enumerate(nums):`**

这行和方法一的 `for i in range(len(nums))` 作用类似，但更好用。

`enumerate(nums)` 会一边给出格子编号，一边给出格子里的内容：

| 第几轮 | i（编号） | n（内容） |
|---|---|---|
| 1 | 0 | 2 |
| 2 | 1 | 7 |
| 3 | 2 | 11 |
| 4 | 3 | 15 |

如果写 `for i in range(len(nums))`，那 `n` 还得自己用 `nums[i]` 取一次。
`enumerate` 帮你把两件事一起做了，代码更短。

**第 4 行：`need = target - n`**

算出"我还需要谁"。

这行是整个解法的**核心**。它把问题从"我要找两个数"变成了"我只要找一个数"。

**第 5 行：`if need in seen:`**

去登记本里查一下：我需要的这个数，之前出现过吗？

`in` 是 Python 的关键字，意思是"在……里面吗"，结果要么 `True` 要么 `False`。

**第 6 行：`return [seen[need], i]`**

出现过，那就找到了。

- `seen[need]` 是"我需要的那一半，它当时在几号格子"（**之前**的格子）
- `i` 是"当前这个数在几号格子"（**现在**的格子）

按照题目要求的"返回下标"，把这两个编号装进列表返回。

注意顺序：先返回**之前**那个，再返回**现在**这个。题目说顺序无所谓，但通常大家都写成从小到大。

**第 7 行：`seen[n] = i`**

这一步是**登记**：把当前的数字 `n` 和它的编号 `i` 记进登记本。

⚠️ **这一行的位置至关重要**——它必须在"查"的**后面**。

**为什么不先登记再查？** 看示例 3：

```
输入：nums = [3, 3], target = 6

如果是「先登记再查」：
  第 1 轮 i=0, n=3：先登记 seen[3] = 0
                    再查 need = 6-3 = 3 → 3 在 seen 里吗？在！（就是刚登记的自己）
                    → 返回 [seen[3], 0] = [0, 0]  ❌ 同一个格子用了两遍！

如果是「先查再登记」（正确写法）：
  第 1 轮 i=0, n=3：先查 need = 3 → seen 里什么都没有，没找到
                    再登记 seen[3] = 0
  第 2 轮 i=1, n=3：先查 need = 3 → 在！seen[3] = 0
                    → 返回 [0, 1]  ✅
```

**"先查再登记"这个顺序，就是用来防止"自己和自己配对"的。**
换个说法：查的是"我之前有没有见过你"，而刚登记的自己是"现在"，不算"之前"。

**第 8 行：`return []`**

同方法一：题目保证有答案，这行是兜底。

### 拿三个示例全部走一遍

**示例 1：`nums = [2,7,11,15], target = 9`**

| 轮次 | i | n | need = 9-n | need 在 seen 里吗 | 动作 |
|---|---|---|---|---|---|
| 1 | 0 | 2 | 7 | 否（seen 是空的） | 登记 `seen[2] = 0` |
| 2 | 1 | 7 | **2** | **是！`seen[2] = 0`** | 返回 `[0, 1]` ✅ |

**示例 2：`nums = [3,2,4], target = 6`**

| 轮次 | i | n | need = 6-n | need 在 seen 里吗 | 动作 |
|---|---|---|---|---|---|
| 1 | 0 | 3 | 3 | 否 | 登记 `seen[3] = 0` |
| 2 | 1 | 2 | 4 | 否 | 登记 `seen[2] = 1` |
| 3 | 2 | 4 | **2** | **是！`seen[2] = 1`** | 返回 `[1, 2]` ✅ |

注意这里走了 3 轮才找到——**答案在第 2、3 个格子上**。这说明字典不是"第一次就中"，
而是"每走一步都检查一次，直到中"。

**示例 3：`nums = [3,3], target = 6`**

| 轮次 | i | n | need = 6-n | need 在 seen 里吗 | 动作 |
|---|---|---|---|---|---|
| 1 | 0 | 3 | 3 | 否 | 登记 `seen[3] = 0` |
| 2 | 1 | 3 | **3** | **是！`seen[3] = 0`** | 返回 `[0, 1]` ✅ |

第 1 轮查的时候 seen 还是空的，所以不会匹配到自己。

## 两种方法放一起比

| | 方法一：两层循环 | 方法二：字典 |
|---|---|---|
| 代码行数 | 6 行 | 6 行 |
| 看懂要多久 | 快 | 慢一点（要理解字典） |
| 时间复杂度 | O(n²) | **O(n)** |
| 空间复杂度 | O(1)（几乎不占额外内存） | O(n)（要存一个字典） |
| 实测 n = 100,000 | 约 **238 秒**（超时） | **0.019 秒** |
| LeetCode 能过吗 | 数据量大时会超时 | 能过 |

（右侧那 0.019 秒是实测值：这台机器上 `n=100000` 的字典法只花了 19 毫秒。）

**"O(n²)"和"O(n)"是什么意思？**

大 O 用来描述"数据量变大时，耗时的增长速度"，只关心量级、不关心具体常数。

- **O(n²)**：格子数翻倍，耗时变成 **4 倍**。n 从 1000 涨到 2000，时间涨 4 倍。
- **O(n)**：格子数翻倍，耗时也**只翻倍**。线性增长。

所以数据量一大，差距是**指数级拉开**的，不是"快一点点"。

**"用空间换时间"** 是这里的关键trade-off：字典多占了一些内存（存了 n 条记录），
但换来了快到飞起的查找速度。这是算法里最常见的取舍之一。

### 那道题到底该用哪个？

- **面试 / LeetCode 提交** → 用**方法二**。方法一会被判超时，而且面试官想看的正是"你会不会想到用哈希表"。
- **只是理解题目** → 先用**方法一**，因为它不需要任何额外知识就能看懂。

**建议的学法：先自己写出方法一，再想"怎么才能不重复地问前面那些数"，然后你就自然想到方法二了。** 这个"从笨办法过渡到聪明办法"的过程，比直接背下方法二有价值得多。

## 新手最容易踩的三个坑

**坑 1：等号写成一个**
```python
if nums[i] + nums[j] = target:   # ❌ 语法错误
if nums[i] + nums[j] == target:  # ✅ 比较要用两个等号
```

**坑 2：内层循环从 0 开始**
```python
for j in range(len(nums)):      # ❌ 会拿自己配自己
for j in range(i + 1, len(nums)):  # ✅ 只跟后面的配对
```

**坑 3：先登记再查（方法二里）**
```python
seen[n] = i            # ❌ 登记在前
if need in seen: ...   #    会匹配到自己
```
示例 3 `[3,3]` 就是专门用来抓这个错误的用例。

## 附带说明：方法二的代码为什么把 `need` 抽出来

有人会写成这样，更短：

```python
def two_sum(nums, target):
    seen = {}
    for i, n in enumerate(nums):
        if target - n in seen:
            return [seen[target - n], i]
        seen[n] = i
    return []
```

`target - n` 出现了两次。写成变量 `need` 有三个好处：

1. **少算一次**（虽然这点开销可以忽略）
2. **读起来是"我需要谁"这句话**，而不是一串算式
3. 改的时候只改一处

代价是多一行。对新手来说，**可读性比省一行重要**，所以推荐带 `need` 的写法。
