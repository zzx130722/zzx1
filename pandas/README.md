## 练习一：四个动作 + 三个坑

**四个动作**（覆盖 80% 的日常操作）：

| 动作 | 写法 |
|---|---|
| 读文件 | `pd.read_csv(path, encoding="utf-8-sig")` |
| 加派生列 | `df["金额"] = df["数量"] * df["单价"]` |
| 分组聚合 | `df.groupby("列").agg(名字=("列", "函数"))` |
| 变回普通表 | `.reset_index()` |

**三个坑**：

| 坑 | 症状 | 解法 |
|---|---|---|
| 日期是字符串 | 没法 `.dt.month`，报 `AttributeError` | `pd.to_datetime()` |
| 分组字段变成索引 | `KeyError: 'region'`，但列名明明有 | `.reset_index()` |
| BOM 藏在列名里 | `KeyError`，列名看着一模一样 | 读时加 `encoding="utf-8-sig"` |

> 顺带一个实测结论：**pandas 3.0 会自动吃掉 BOM**，用 `utf-8` 读也不会出问题；
> 但标准库 `csv` 不会 —— 它读出来的第一列名是 `'\ufefforder_date'`。
> notebook 里两段代码放在一起对比了。

## 练习二：三条铁律

| 铁律 | 为什么 |
|---|---|
| **`dropna()` 必须带 `subset`** | 不带等于「删掉任何有空值的行」，40 行直接变 35 行，删掉 12.5% |
| **金额类缺失不能填 0** | 0 是「没有」，不是「不知道」。总额可能不变，但**均值和计数全错** |
| **merge 前必查主键唯一性** | 不查就会行数膨胀、金额算两遍，而且事后极难定位 |

**最值得记住的一个实测结果**：

```
         处理方式     总金额     平均值  计数
0          填 0  18270.0  456.75  40
1        填中位数  19192.0  479.80  40
2      删除缺失行  18270.0  480.79  38
```

**「填 0」和「删除缺失行」的总金额完全相同** —— 因为 `sum()` 本来就会跳过 `NaN`，加 0 不改变和。

所以：**如果你只核对总额，永远发现不了「填 0」是错的**。错的是均值和计数 ——
把 2 笔"未知"当成 2 笔"0 元订单"，均值从 480.79 掉到 456.75，计数从 38 变成 40。

这就是脏数据最阴的地方：**它不报错，而且错在你没在看的那个指标上。**

**merge 的三步检查清单**（可以直接背下来）：

```python
# 1. 合并前：右表主键唯一吗？
assert len(customers) == customers["customer_id"].nunique()

# 2. 合并后：行数对得上吗？
assert len(merged) == len(orders)

# 3. 有多少没匹配上？
orders.merge(customers, on="customer_id", how="left", indicator=True)["_merge"].value_counts()
```
