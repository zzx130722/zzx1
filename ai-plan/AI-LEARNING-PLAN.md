# AI 学习计划 · 12 周（项目驱动）

> 制定日期：2026-10-19
> 设定条件：**目标是能独立做出 AI 应用**；每周投入 **8-10 小时**；已有 Python 基础（做过 8 道 LeetCode、会建 venv、会用 Git）
> 如果你每周只有 5 小时或能投入 20 小时以上，直接看文末「八、时间缩放」

## 一、先说清楚这个计划「不做什么」

新手最容易死在「学不完」上，所以先把范围砍掉：

| 不做 | 为什么 |
|---|---|
| 不背机器学习公式、不推导反向传播 | 你的目标是做应用，不是训模型。需要时再补 |
| 不上来就学 LangChain / LlamaIndex | 框架半年一变，`messages` 数组、HTTP、JSON 这些十年不变 |
| 不看完 40 小时视频课再动手 | 项目驱动的前提是**第一天就有能跑的东西** |
| 不追求「学完」，只追求「能交付」 | 验收标准是「能演示、能讲清、能改动」，不是「看过」 |

**一句话原则：每两周必须有一个别人能点开、能跑、能看懂的东西。**

## 二、12 周后你手里应该有什么

三个作品，从简单到复杂，每个都能写进简历／发给朋友试：

| # | 作品 | 练到的能力 | 验收（达不到就不算完成） |
|---|---|---|---|
| A | **命令行 AI 助手** | 调 API、多轮对话、流式输出、超时重试、成本统计 | 能连续对话 10 轮不崩；断网/超时能自动重试；能报出本次花了多少钱 |
| B | **个人知识库问答（RAG）** | 文档切分、向量检索、引用溯源、效果评估 | 20 个自测问题答对 **≥16 个**，且每条答案能指出「出自哪个文件第几段」 |
| C | **会用工具的 Agent** | function calling、多步规划、失败处理、人工确认 | 完成 5 个真实任务（如「查本周 LeetCode 进度并生成周报」），其中 1 个必须**失败得优雅** |

> 三个作品共用一套代码骨架：`config`（读 key）→ `llm`（调模型）→ `app`（业务）。做完 A 之后，B 和 C 是在同一棵树上长出来的，不是从零开始。

## 三、四个阶段

### 阶段 0 · 第 1 周（10/19 - 10/25）：补地基，正好把欠的 pandas 还掉

**为什么先做这个**：90% 的 AI 应用本质是「发 HTTP 请求 → 拿到 JSON → 处理数据 → 再发一次」。这三件事不熟，后面全是玄学。

| 天 | 任务 | 产出 |
|---|---|---|
| 周一 | 搞懂 HTTP 和 JSON：用 `requests` 调一个公开 API（如天气、汇率），打印结果 | `week1/http_demo.py` |
| 周二 | 异常处理：超时、404、返回不是 JSON 怎么办 | 同上，加 `try/except` |
| 周三 | 环境变量：`os.environ` + `.env` 文件 + 确认 `.gitignore` 生效 | `.env.example`（真 key 不进 Git） |
| 周四 | pandas ①：读 CSV + `groupby` 聚合（任务三欠的第一个 notebook） | `pandas/01_groupby.ipynb` |
| 周五 | pandas ②：缺失值处理 + `merge`（欠的第二个 notebook） | `pandas/02_merge.ipynb` |
| 周末 | 小项目：调公开 API 取 100 条数据 → 存 CSV → pandas 聚合 → 打印前 5 名 | `week1/mini_report.py` |

**阶段验收**
- [ ] `python week1/mini_report.py` 一条命令跑出结果，不需要手动改任何变量
- [ ] 故意断网，程序给出人能看懂的错误，而不是一堆 traceback
- [ ] `.env` 里的内容 `git status` 看不到

### 阶段 1 · 第 2-3 周（10/26 - 11/8）：项目 A · 命令行 AI 助手

**目标**：不借助任何框架，用 `requests` 直接调模型 API，把「一次问答」做成「一个能聊天的程序」。

**第 2 周：跑通最小的那条路**
| 天 | 任务 |
|---|---|
| 周一 | 选一个国内可用的模型厂商（DeepSeek / 通义千问 / 智谱 GLM / Kimi 任选），注册拿 API key |
| 周二 | 用 `curl` 发一次请求，看到返回的 JSON（**先别写 Python**，先确认 key 和网络通） |
| 周三 | 换成 Python `requests`，封装 `chat(messages) -> str` |
| 周四 | 加 `system` 角色，让它的回答风格可控 |
| 周五 | 加多轮：把历史 `messages` 带上，实现「它记得上一句」 |
| 周末 | 加一个 `while True` 的命令行循环，能连续聊 |

**第 3 周：把它变成「能用的工具」**
| 天 | 任务 |
|---|---|
| 周一 | 流式输出（边生成边打印，而不是等 10 秒一次性吐出来） |
| 周二 | 超时 + 重试：`timeout=30`，失败重试 3 次，指数退避 |
| 周三 | 错误分类：401（key 错）、429（限流）、5xx（服务端）分别给人话提示 |
| 周四 | 统计 token 与费用：每次请求记录 `prompt_tokens` / `completion_tokens`，累加 |
| 周五 | 上下文裁剪：超过 N 轮就丢掉最早的对话（否则越聊越贵、最后超长报错） |
| 周末 | 写 `README.md`：怎么装、怎么配 key、怎么跑；录 1 分钟演示 |

**阶段验收**
- [ ] 换一个模型厂商，只改 `config.py` 里两行（`base_url` + `model`），业务代码不动
- [ ] 拔网线 → 程序重试 3 次后给出「网络不可用，请检查代理」而不是崩掉
- [ ] 连续对话 20 轮，程序不崩、费用可见
- [ ] 能回答：「为什么要把 `assistant` 的历史消息也放回 `messages`？」（不放进会怎样）

**常见坑**
1. **把 key 写进代码** → 提交到 GitHub 后会被扫号盗刷。只用 `.env`，且 `.env` 必须在 `.gitignore` 里
2. **上下文无限增长** → 每轮把全部历史发回去，token 线性上涨，最后报「超出上下文长度」
3. **以为流式很难** → 本质是「按行读 SSE，剥掉 `data: ` 前缀，遇到 `[DONE]` 停」

### 阶段 2 · 第 4-6 周（11/9 - 11/29）：项目 B · 个人知识库问答（RAG）

**目标**：让模型回答「你自己文档里」的内容，并且**说得出出处**。

**第 4 周：先做「没有向量」的 RAG**
- 把 `dev-basics` 里的 markdown 全部切段（按标题 / 空行切，每段 300-500 字，带 overlap）
- 用**关键词匹配**（BM25 或最简单的「包含几个查询词」打分）检索出 top-5 段
- 拼进 prompt：「只根据以下资料回答，资料里没有就说不知道」
- **这一周不碰 embedding**。目的是先看清 RAG 的骨架：`切分 → 检索 → 拼 prompt → 生成`

**第 5 周：换成向量检索**
- 调厂商的 embedding API（或本地 `bge-small-zh-v1.5`），把每段变成向量
- 用 numpy 手写余弦相似度（几千段以内根本不需要向量数据库）
- 对比第 4 周的结果：哪些问题变好了、哪些变差了
- 第 6 周再考虑引入 FAISS / Chroma —— **先证明你需要它**

**第 6 周：引用溯源 + 评估**
- 回答里强制带 `[来源: 文件名#段落号]`
- 建 **20 个问题的评估集**（10 个能从文档里找到答案、5 个需要跨文件、5 个文档里没有）
- 人工打分并记录到 CSV：答对 / 答错 / 该说「不知道」却编了
- 针对最差的 3 个问题做一次优化（改切分、改 top-k、改 prompt）

**阶段验收**
- [ ] 20 个问题答对 ≥16 个
- [ ] 5 个「文档里没有」的问题，至少 4 个回答「资料中未找到」，而不是编造
- [ ] 每个答案都能点回原文位置
- [ ] 能回答：「为什么切分粒度太大会漏、太小会断章取义？」

**关键认知**：RAG 效果差，**八成不是模型不行，是切分和检索不行**。先怀疑检索结果里有没有正确答案，再怀疑模型。

### 阶段 3 · 第 7-9 周（11/30 - 12/20）：项目 C · 会调工具的 Agent

**目标**：模型不再只是「说」，而是能「决定调用你的函数」，并根据结果继续下一步。

**第 7 周：理解 function calling**
- 关键点：**模型不会真的执行任何东西**，它只输出「我要调用 `get_weather`，参数是 `{"city":"北京"}`」，执行是你的代码做的
- 定义 3 个工具：`read_file(path)`、`query_csv(question)`（包一层 pandas）、`http_get(url)`
- 实现循环：模型要工具 → 你执行 → 把结果作为 `tool` 消息喂回去 → 模型继续
- 加 `max_steps=8`，防止死循环

**第 8 周：让它可靠**
- 工具参数校验：模型给错参数（少字段、类型错）时不崩，把错误信息回喂给模型让它重试
- 失败重试：同一个工具连续失败 2 次就换策略或直接告知用户
- **危险操作人工确认**：写文件、删文件、发请求前必须 `input("确认执行? y/n")`
- 日志：每一步的「思考 → 工具 → 结果」都落盘，方便事后复盘

**第 9 周：做一个真任务**
- 任务示例：「扫描 `leetcode/` 目录，统计每个文件的用例数，生成周报 markdown」
- 要求：能自己决定先读哪些文件、算出统计、写出 `weekly.md`
- 再做一个**注定失败**的任务（比如查一个不存在的文件），验收它是否优雅退出

**阶段验收**
- [ ] 5 个真实任务里至少 4 个能独立完成
- [ ] 失败任务不会死循环、不会假装成功
- [ ] 危险操作一定会停下来问人
- [ ] 能回答：「Agent 和普通对话的本质区别是什么？」（前者有「行动 → 观察」的闭环）

前 9 周做出的是「能跑的脚本」，这三周把它变成「别人能用的产品」。

## 五、学习资源：少而精

| 类型 | 推荐 | 说明 |
|---|---|---|
| 首选 | **模型厂商官方 API 文档** | 看「快速开始」和「function calling」两页就够，别通读 |
| 首选 | Python 官方文档 / `requests` 文档 | 遇到参数不懂时查，不要看二手教程 |
| 首选 | pandas 官方「10 minutes to pandas」 | 比任何视频课都准 |
| 可选 | 任意一门「LLM 应用开发」短课 | 只挑「RAG」「Agent」两章看，别从头刷 |
| 不推荐 | 40 小时全集视频课 | 项目驱动路线下，性价比极低 |

**遇到问题的顺序**：读完整报错 → 官方文档搜关键词 → 自己改一处试一次 → 再问 AI。
问 AI 时**必须带**：完整报错、相关代码、你已经试过什么。

## 六、验收标准：三层，缺一不算过

| 层级 | 标准 | 怎么自测 |
|---|---|---|
| 能演示 | 别人按 README 能跑起来 | 找一个没参与的人试，你别说话 |
| 能讲清 | 能画出数据流，说清每一步为什么这么做 | 对着白纸讲 3 分钟，卡住的地方就是没懂 |
| 能改动 | 改一个需求（换模型、加一个工具、换切分方式）能在 1 小时内完成 | 现场改，不许查自己以前的代码 |

每阶段结束写 5 行复盘：**做了什么 / 卡在哪 / 怎么解决 / 下次改什么 / 还剩什么**。

## 七、新手最容易踩的 6 个坑

1. **key 进了 Git** —— 提交前 `git status` 看一眼，`.env` 必须在 `.gitignore`
2. **一上来学框架** —— 连 `messages` 结构都没搞懂就上 LangChain，出错完全无法排查
3. **只看不写** —— 视频看懂 ≠ 能写。每天必须有代码产出
4. **上下文无限增长** —— 越聊越贵、最后超长报错。第 3 周就要处理
5. **不做评估，凭感觉说「效果不错」** —— 没有 20 题评估集，你无法判断改动是变好还是变坏
6. **项目太大做不完** —— 每个项目先做「最小可运行」，跑通再加一个能力

## 八、时间缩放

## 九、第 1 周今天就能做的 5 件事

1. **建目录**：`ai-plan/week1/`，并 `git commit` 一次（空目录放个 `README.md` 才能提交）
2. **申请一个模型 API key**：DeepSeek / 通义千问 / 智谱 GLM / Kimi 任选一家，先确认有免费额度
3. **用 `curl` 打通一次**（不写 Python）：能看到返回的 JSON，就说明 key 和网络都没问题
4. **建 `.env` + `.env.example`**，把真 key 放 `.env`，然后 `git status` 确认它没被追踪
5. **把 pandas 两个 notebook 建起来** —— 这就是任务三欠的最后一项，顺手还掉

> 做完这 5 件，第 1 周就过去一半了。**别等到「准备好了」再开始，第 1 件事现在就能做。**
