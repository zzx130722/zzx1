# 里程碑 1 · 三道小题，全程自己写

这是学习计划第 2 周那行的最后一格：**「给定 3 个小任务（如脏 CSV 清洗＋统计报告），全程 AI 辅助独立完成，能逐行讲清逻辑」**。

规则只有一条：**AI 可以问，代码得你自己敲。** 问「这个函数叫什么」「为什么我这里是 NaN」都行；
问「帮我把这题写完」——那就等于这题没做。

三道题一共大约 60–90 分钟，比 LeetCode 简单，但比 LeetCode 真实：
真实工作的数据从来不是干净整齐的，而输出格式是别人指定的，你说不上话。

---

## 怎么跑

写三个脚本（叫什么都行，放你自己习惯的地方），让它们分别生成 `out/` 下的三个产物：

```powershell
cd $HOME\WorkBuddy\2026-10-13-16-35-32\dev-basics
.venv\Scripts\python.exe -X utf8 ai-engineering\05-milestone\grade.py
```

判分器会逐项告诉你过没过、哪一项不对、以及「第几条不一样」。
退出码 0 = 三题全过。**它不会替你写，也不会告诉你「该改成什么」。**

> ⚠️ `grade.py` 文件末尾 `EXPECTED_*` 就是完整答案。先自己写，卡住再看。
> 直接抄的话，这个练习对你的价值是 0 —— 而且你会在下面的「讲清逻辑」环节露馅。

## 第 1 题：清洗 `data/raw_orders.csv` → `out/t1_clean.csv`

原始数据 14 行，脏在四个地方，**每一处都要按下面规则处理**（规则是我定的，别自己发挥）：

| 脏法 | 规则 |
|---|---|
| `order_id` 有重复 | 同一 id 保留 `order_date` **最新**的那条；日期相同则保留文件里**靠后**出现的那条 |
| `region` 大小写不统一、带空格、有空值 | 去空格 + 首字母大写（`north` → `North`）；空值填 `UNKNOWN` |
| `amount` 带 `$`、带千分位逗号、有空值 | 去掉 `$` 和 `,` 转成数字；**空值这一行直接丢弃** |
| `order_date` 有 `2026-01-05` 和 `2026/2/20` 两种 | 统一成 `YYYY-MM-DD`，月份日期补零 |

输出要求（判分器按这个逐字比对）：

```
order_id,customer_id,region,order_date,amount,channel
1001,C-07,North,2026-01-05,120.00,web
...
```

- 表头一字不差，列顺序同上
- 按 `order_id` **升序**
- `amount` 固定两位小数（`0` 要写成 `0.00`，`15.5` 要写成 `15.50`）
- 不留空行、不加索引列

**三个最容易错的地方**：`"$1,340.50"` 里那个逗号会让 `line.split(",")` 直接错位（用 `csv` 模块，别自己切）；
`2026/2/20` 是「月/日」不是「日/月」；去重的比较键是**日期**，不是出现顺序。

## 第 2 题：按 region 汇总 → `out/t2_report.txt`

读**你第 1 题的输出**（不是原始数据），按 `region` 汇总，输出制表符分隔的四列：

```
region	orders	total	avg
East	1	0.00	0.00
North	4	...
TOTAL	...
```

- 第一行是表头，字段名一字不差
- region 行按**字母升序**（`East` < `North` < `South` < `UNKNOWN` < `West`）
- 最后一行是 `TOTAL`，统计全部
- `total` / `avg` 保留两位小数（判分时容差 0.005，不用担心四舍五入方向）

**最容易错**：`avg` 的分母是**行数**不是 `total` 的位数；`TOTAL` 的 `avg` 是「总额 ÷ 总单数」，
不是「各 region 均值的平均」——这两个数不一样，前者才对。

## 第 3 题：日志按月统计 → `out/t3_hits.tsv`

`data/hits.log` 是 12 行 nginx 风格的访问日志，其中**有 2 行是坏的**（一行没有 URL，一行时间戳是
`not-a-timestamp`）。统计「每个月里每个 URL 被请求了几次」：

```
2026-01	/blog/mapreduce	1
2026-01	/index.html	2
...
#dropped	2
```

- 三列制表符分隔：`YYYY-MM`、URL、次数
- 按 `(月份, url)` 升序
- 坏行**跳过但要计数**，最后一行写 `#dropped` + 制表符 + 坏行数
- URL 取**请求行**里的路径（`"GET /index.html HTTP/1.1"` 中间那个），不是 Referer

> 这题和 `01-read-code/mapreduce-lab/` 那节讲的是同一件事。
> 差别是：那边用 mrjob 框架，这边只让你用标准库。**自己写一遍才知道框架替你做了什么。**

**最容易错**：用 `line.split()` 取请求路径会被 URL 里的特殊字符和 UA 的空格搞乱，用正则；
`/Jan/` 要映射成 `01`；坏行计数**不能**只数「没解析出 URL 的」，时间戳坏的那行同样要算。

## 三题全过之后：这一格才算真正完成

判分器只验产物，验不了「你有没有懂」。计划里那句**「能逐行讲清逻辑」**要你自己过一遍，
下面六问，每题用两句话答（写在纸上，或者直接说给自己听）：

1. 第 1 题里，同一个 `order_id` 出现两次时，你的代码是**怎么决定留哪条**的？逐步说。
2. `"$1,340.50"` 你是怎么变回数字的？为什么要用 `csv` 模块而不是 `split(",")`？
3. `2026/2/20` 你的代码怎么知道是 2 月 20 日而不是 20 月 2 日？
4. 第 2 题的 `TOTAL.avg` 你怎么算的？如果错写成「各 region 均值再平均」，数字会变成多少？
5. 第 3 题里那两行坏日志，你的代码是**在哪一步**发现它们坏的？
6. 如果日志从 12 行变成 1200 万行，你的第 3 题代码还能跑吗？哪一行会先撑不住？

第 6 问答不上来是正常的——它正好接上 `mapreduce-lab` 那节：**为什么单机脚本处理不了 TB 级数据，
以及 MapReduce 到底替你解决了什么。**

答完之后，去 `PROGRESS.md` 里把这一格勾掉。
